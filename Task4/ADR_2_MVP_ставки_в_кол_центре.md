### <a name="_qmphm5d6rvi3"></a>**Решение**

- [Диаграмма контекста  в модели C4](./C4_Context_Diagram_кол_центр.puml)
- [Диаграмма контейнеров в модели C4](./C4_Container_Diagram_кол_центр.puml)

**Детализируем изменения в архитектуре MVP для интеграции кол-центра:**

a. **Интеграция Rate Service с системой кол-центра.** Создаем REST API в Rate Service для предоставления актуальных ставок системе кол-центра. Это обеспечивает реальное время консультирования клиентов.

b. **Система передачи файлов ставок партнёру.** Разрабатываем File Transfer Service, который автоматически генерирует файлы со ставками и передает их партнёрскому кол-центру через SFTP. Это решает ограничение партнёра на отсутствие API.

c. **Масштабирование кол-центра.** Интегрируем систему маршрутизации звонков, которая может перенаправлять часть нагрузки на партнёрский кол-центр при пиковых нагрузках.

d. **Синхронизация ставок в реальном времени.** Rate Service уведомляет все подключенные системы (кол-центр, файловый сервис) об изменениях ставок через события.

e. **Безопасность передачи файлов.** Используем SFTP с шифрованием, IP-фильтрацией и логированием для безопасной передачи конфиденциальных данных партнёру.

**Новые компоненты системы:**

1. **File Transfer Service** - сервис для генерации и передачи файлов ставок партнёру
2. **Call Routing Service** - сервис маршрутизации звонков между кол-центрами  
3. **Rate API Gateway** - API-шлюз для Rate Service с кэшированием и rate limiting
4. **File Storage** - хранилище для временных файлов ставок
5. **SFTP Server** - сервер для безопасной передачи файлов партнёру

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

**Альтернатива 1: Прямая интеграция Rate Service с партнёрским кол-центром через API**

*Описание:* Создание прямого API-интерфейса между Rate Service и партнёрским кол-центром, минуя файловую передачу.

*Преимущества:*
- Реальное время обновления ставок
- Упрощение архитектуры
- Отсутствие промежуточных файлов
- Прямая синхронизация данных

*Недостатки:*
- Нарушение требования партнёра на отсутствие API
- Необходимость изменения архитектуры партнёра
- Потенциальные проблемы с безопасностью
- Сложность интеграции с внешней системой

**Альтернатива 2: Использование веб-сервисов вместо файлов**

*Описание:* Создание веб-интерфейса для партнёрского кол-центра, где сотрудники могут просматривать актуальные ставки через браузер.

*Преимущества:*
- Реальное время обновления
- Простота реализации
- Отсутствие файловых операций
- Универсальный доступ

*Недостатки:*
- Нарушение требования на файловую передачу
- Необходимость постоянного интернет-соединения
- Потенциальные проблемы с производительностью
- Сложность кэширования данных

**Альтернатива 3: Использование базы данных для синхронизации**

*Описание:* Создание общей базы данных или репликации между банком и партнёрским кол-центром для синхронизации ставок.

*Преимущества:*
- Прямая синхронизация данных
- Высокая производительность
- Отсутствие файловых операций
- Надежность передачи данных

*Недостатки:*
- Нарушение изоляции систем
- Проблемы с безопасностью
- Сложность настройки репликации
- Зависимость от сетевого соединения

### <a name="_недостатки_ограничения_риски"></a>**Недостатки, ограничения, риски**

**Недостатки выбранного решения:**

1. **Задержка синхронизации:** Файловая передача создает задержку в обновлении ставок у партнёра (до 5 минут).

2. **Сложность управления файлами:** Необходимость очистки временных файлов, мониторинга передачи, обработки ошибок.

3. **Дополнительная инфраструктура:** File Transfer Service и SFTP Server требуют дополнительных ресурсов и поддержки.

4. **Потенциальные проблемы с форматом:** Необходимость поддержки различных форматов файлов, совместимости с системами партнёра.

**Ограничения:**

1. **Технические ограничения SFTP:** Ограничения на размер файлов, скорость передачи, количество одновременных соединений.

2. **Ограничения файлового формата:** Необходимость поддержки только CSV/XML форматов, принятых партнёром.

3. **Сетевые ограничения:** Зависимость от качества интернет-соединения между банком и партнёром.

4. **Ограничения безопасности:** Необходимость использования только SFTP, отсутствие возможности использования более современных протоколов.

**Риски:**

1. **Риск потери файлов:** При сбоях в передаче файлов партнёр может получить устаревшие ставки.

2. **Риск нарушения безопасности:** Передача файлов через интернет создает риски утечки конфиденциальной информации.

3. **Риск рассинхронизации:** Различное время обновления ставок в разных системах может привести к путанице.

4. **Риск перегрузки файловой системы:** При частых изменениях ставок может возникнуть перегрузка системы передачи файлов.

5. **Риск vendor lock-in:** Привязка к конкретному формату файлов и протоколу передачи может ограничить возможности смены партнёра.

6. **Риск сложности поддержки:** Увеличение количества компонентов усложняет диагностику проблем и поддержку системы.
